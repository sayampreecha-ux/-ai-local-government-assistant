# GovPrompt Thailand — Day 5 Privacy Governance Baseline

สถานะ: Internal Pilot
วันที่: 9 สิงหาคม 2569

> เอกสารนี้เป็นกรอบกำกับดูแลภายในสำหรับลดความเสี่ยงด้านข้อมูลส่วนบุคคลและความมั่นคงปลอดภัย ไม่ใช่คำรับรองทางกฎหมาย และไม่แทนการพิจารณาของ DPO/ฝ่ายกฎหมายของหน่วยงานที่นำระบบไปใช้จริง

## 1. หลักการบังคับใช้กับ GovPrompt

1. **Privacy by Design** — ออกแบบให้ใช้ข้อมูลส่วนบุคคลให้น้อยที่สุดตั้งแต่ต้น
2. **Data Minimization** — ใช้เฉพาะข้อมูลที่จำเป็นต่อวัตถุประสงค์ของงาน
3. **Anonymization / Redaction First** — ปกปิดข้อมูลระบุตัวบุคคลก่อนค้นภายนอกหรือส่งต่อบริการอื่น
4. **Defense in Depth** — ตรวจข้อมูลเสี่ยงทั้ง Browser Privacy Guard และ Worker
5. **Fail Closed** — ถ้าตรวจพบข้อมูลเสี่ยงสูงหรือไม่มั่นใจ ให้หยุด external search
6. **No Secret in Logs** — ห้าม log full prompt, raw query, password, token, API key หรือข้อมูลลับ
7. **Human Review** — AI ไม่อนุมัติ ไม่สั่งการ และไม่วินิจฉัยแทนผู้มีอำนาจ
8. **Purpose Limitation** — ใช้ข้อมูลเพื่อช่วยค้น วิเคราะห์ และร่างงานตามคำขอเท่านั้น
9. **Retention Minimization** — ไม่สร้างการเก็บประวัติข้อความ/เอกสารโดยไม่จำเป็น
10. **Incident Ready** — ต้องมีขั้นตอนรับมือเหตุละเมิดและบันทึกเหตุการณ์

## 2. ขอบเขตการใช้ระหว่าง Internal Pilot

### อนุญาต
- ค้นกฎหมาย ระเบียบ หนังสือสั่งการ และแหล่งราชการ
- ตรวจ TOR โดยใช้ข้อมูลที่ไม่ระบุตัวบุคคล
- ร่างหนังสือราชการจากข้อมูลสมมติหรือข้อมูลที่ปกปิดแล้ว
- วิเคราะห์แผน งบประมาณ พัสดุ การเงิน บุคคล สภา สาธารณสุข และงานช่าง โดยตัดข้อมูลส่วนบุคคลที่ไม่จำเป็นออก
- ทดสอบด้วยเอกสารจำลองหรือเอกสาร de-identified

### ยังไม่อนุญาต
- ข้อมูลลับของราชการหรือข้อมูลความมั่นคง
- password, API key, token, private key
- ฐานข้อมูลประชาชนหรือทะเบียนบุคคล
- เลขบัตรประชาชน เลขบัญชี HN/AN หรือข้อมูลสุขภาพจริงที่ไม่จำเป็น
- การตัดสินใจอัตโนมัติที่มีผลต่อสิทธิ บุคคล เงิน วินัย การแต่งตั้ง หรือการอนุมัติราชการ
- การใช้ GovPrompt เป็นระบบเก็บเอกสารทางการ

## 3. Data Flow ที่ต้องเปิดเผยแก่ผู้ใช้

เมื่อใช้ Live Official Search:

```text
Browser
  -> Privacy Guard
  -> Cloudflare Worker
  -> Server-side Sensitive Data Check
  -> Tavily Search API
  -> Official-domain filtered results
  -> Browser
```

ข้อสำคัญ:
- Worker ไม่ควร echo raw query กลับใน response
- application log ต้องเก็บเฉพาะ metadata ที่จำเป็น
- upstream search provider เป็นบริการภายนอก จึงต้องห้ามส่งข้อมูลลับหรือข้อมูลส่วนบุคคลจริงที่ไม่จำเป็น
- เมื่อผู้ใช้กดเปิดใน ChatGPT การคัดลอก/วาง Prompt และการแนบไฟล์ใน ChatGPT เป็น data flow แยกอีกเส้นทางหนึ่ง

## 4. Privacy Notice Minimum Content ก่อน Public Pilot

ก่อนเปิดใช้งานวงกว้าง ควรมีประกาศความเป็นส่วนตัวที่ระบุอย่างน้อย:
- ผู้ดูแล/ผู้รับผิดชอบโครงการในช่วง Pilot
- วัตถุประสงค์ของการประมวลผล
- ประเภทข้อมูลที่ระบบอาจรับ
- ข้อมูลที่ห้ามกรอก
- ผู้ให้บริการภายนอก/ปลายทางข้อมูลที่เกี่ยวข้อง
- หลักการหรือระยะเวลาเก็บข้อมูล/Logs
- มาตรการความมั่นคงปลอดภัยโดยสรุป
- ช่องทางแจ้งเหตุหรือสอบถามเรื่องข้อมูลส่วนบุคคล
- สิทธิของเจ้าของข้อมูลในกรณีที่โครงการเป็นผู้ควบคุมหรือผู้ประมวลผลข้อมูลตามกฎหมาย
- การเปลี่ยนแปลงประกาศ

## 5. Controller / Processor Checkpoint

ก่อนหน่วยงานใดใช้ GovPrompt กับข้อมูลจริง ต้องระบุให้ชัดว่า:
- ใครเป็นผู้ควบคุมข้อมูลส่วนบุคคล
- GovPrompt หรือผู้ให้บริการภายนอกอยู่ในฐานะใด
- มีข้อตกลง/คำสั่ง/ฐานอำนาจใดรองรับการประมวลผล
- มี DPO หรือผู้รับผิดชอบของหน่วยงานใดเป็นผู้พิจารณา
- มีการส่งหรือโอนข้อมูลไปต่างประเทศหรือไม่ และต้องดำเนินการอย่างไร

**ห้ามสมมติบทบาทเหล่านี้จากการที่ระบบถูกใช้ในหน่วยงาน** ต้องพิจารณาตามข้อเท็จจริงของการใช้งานจริง

## 6. Go / No-Go Gate ก่อน Public Pilot

ต้องผ่านทั้งหมดก่อนเปิดรับข้อมูลจริงในวงกว้าง:

- [x] Browser Privacy Guard
- [x] Fail Closed สำหรับข้อมูลเสี่ยงสูง
- [x] Worker-side Sensitive Data Check
- [x] Strict Origin Gate
- [x] Request Size Limit
- [x] Rate Limit configuration
- [x] No raw query echo in Worker response
- [x] External provider จำกัดโดเมนราชการ
- [x] Data Flow baseline documented
- [ ] ตรวจ Cloudflare Dashboard จริง: secret / deploy / logs / access
- [ ] Network audit จริงจาก browser ทุก flow สำคัญ
- [ ] ตรวจชื่อไฟล์/attachment metadata ไม่ให้มี PII หลุด
- [ ] Privacy Notice ฉบับพร้อมใช้
- [ ] Incident Response owner + contact tree
- [ ] DPO/ฝ่ายกฎหมายของหน่วยงานทบทวนก่อนใช้ข้อมูลจริง
- [ ] DPIA screening และทำ DPIA ถ้าลักษณะการประมวลผลเข้าข่ายความเสี่ยงสูง

## 7. แนวทาง Incident

หากสงสัยว่ามีข้อมูลรั่ว:
1. หยุด external function ที่เกี่ยวข้องก่อน
2. เก็บหลักฐานเชิงเทคนิคโดยไม่สร้างสำเนาข้อมูลส่วนบุคคลเพิ่มโดยไม่จำเป็น
3. ระบุชนิดข้อมูล จำนวนเจ้าของข้อมูล ระบบ/ผู้ให้บริการที่เกี่ยวข้อง และช่วงเวลา
4. แจ้งผู้รับผิดชอบโครงการและ DPO/ฝ่ายกฎหมายของหน่วยงานที่เกี่ยวข้อง
5. ประเมินความเสี่ยงต่อสิทธิและเสรีภาพของเจ้าของข้อมูล
6. ดำเนินการแจ้งสำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคลและ/หรือเจ้าของข้อมูลตามเงื่อนไขและระยะเวลาที่กฎหมายกำหนด หากเข้าเกณฑ์
7. แก้ root cause และบันทึก post-incident review

## 8. เกณฑ์การสื่อสารต่อสาธารณะ

ใช้คำว่า:
- “Internal Pilot / ทดลองใช้ภายใน”
- “มีมาตรการลดความเสี่ยงด้านข้อมูล แต่ไม่ควรใส่ข้อมูลลับหรือข้อมูลส่วนบุคคลที่ไม่จำเป็น”
- “ผลลัพธ์ต้องตรวจสอบโดยเจ้าหน้าที่ก่อนใช้จริง”

หลีกเลี่ยงคำว่า:
- “ปลอดภัย 100%”
- “PDPA compliant แล้ว” หากยังไม่มีการประเมินตามบทบาทและข้อเท็จจริงครบ
- “ข้อมูลไม่ออกจากระบบเลย” เพราะ live search มี external processing
- “ไม่เก็บข้อมูลใด ๆ” หากยังไม่ได้ยืนยันทุกชั้นของ infrastructure/provider
