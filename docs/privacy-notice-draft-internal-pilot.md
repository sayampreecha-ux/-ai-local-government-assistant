## 2. สถานะและขอบเขตการใช้งาน

GovPrompt อยู่ในช่วง **Internal Pilot / ทดลองใช้ภายใน** ไม่ใช่ระบบราชการทางการ และไม่ใช้แทนระบบสารบรรณ การเงิน พัสดุ ระบบอนุมัติ หรือการตัดสินใจของผู้มีอำนาจ

ผู้ใช้ต้องไม่ใส่ข้อมูลลับของราชการ ข้อมูลส่วนบุคคล หรือข้อมูลอ่อนไหวที่ไม่จำเป็น และควรใช้ข้อมูลจำลองหรือข้อมูลที่ผ่านการปกปิดตัวระบุบุคคลในช่วงทดลอง

## 3. ข้อมูลที่อาจเกี่ยวข้องกับการใช้งาน

ตาม architecture ปัจจุบัน อาจเกี่ยวข้องกับข้อมูลต่อไปนี้:

- ข้อความคำถามที่ผู้ใช้พิมพ์
- ชื่อไฟล์ที่ผู้ใช้เลือกแนบในหน้า Home
- คำค้นที่ผ่าน Privacy Guard ก่อนใช้ live official search
- technical/operational metadata เช่น request ID, ความยาวคำค้น, จำนวนแหล่งค้น, เวลาตอบสนอง และสถานะการทำงาน
- ข้อมูลมาตรฐานที่ผู้ให้บริการโครงสร้างพื้นฐานอาจประมวลผลในการให้บริการเว็บ/API ตามนโยบายของผู้ให้บริการนั้น

GovPrompt ไม่ได้ออกแบบมาเพื่อเก็บฐานข้อมูลประชาชน เอกสารลับ หรือข้อมูลสุขภาพของบุคคล

## 4. วัตถุประสงค์ของการประมวลผล

เฉพาะช่วง Internal Pilot วัตถุประสงค์หลัก ได้แก่:

1. จำแนกประเภทงานราชการและเตรียม prompt/context
2. ค้นหาเอกสารและแหล่งราชการที่เกี่ยวข้อง
3. แสดงผลการค้นและหลักฐานสำหรับให้ผู้ใช้ตรวจสอบ
4. ป้องกัน abuse และตรวจเหตุขัดข้อง/เหตุด้านความปลอดภัย
5. ทดสอบและปรับปรุงความถูกต้อง ความปลอดภัย และ usability ของระบบ

> [ต้องยืนยันก่อนเผยแพร่] ฐานกฎหมายของแต่ละวัตถุประสงค์ตามบทบาทของผู้ควบคุมข้อมูลและ use case จริง ห้ามใช้ “ความยินยอม” เป็นฐานเริ่มต้นโดยอัตโนมัติหากมีฐานกฎหมายอื่นที่เหมาะสมกว่า

## 5. การป้องกันข้อมูลก่อนค้นภายนอก

GovPrompt ใช้มาตรการแบบ Defense in Depth:

- Privacy Guard ฝั่ง browser เพื่อลด/ปกปิดตัวระบุที่ตรวจพบก่อน external search
- server-side sensitive-data check ที่ Cloudflare Worker
- หากตรวจพบข้อมูลเสี่ยงสูง ระบบอาจหยุดการค้นภายนอก (fail closed)
- จำกัด origin, ขนาด request และอัตราการเรียก API
- ไม่ตั้งใจบันทึก raw query เต็มลง application log
- ไม่ echo raw query กลับใน API response

ตัวกรองเป็นระบบ rule/regex-based และไม่สามารถรับประกันการตรวจพบข้อมูลส่วนบุคคลได้ทุกกรณี ผู้ใช้จึงยังมีหน้าที่ลดข้อมูลและปกปิดข้อมูลก่อนใช้งาน

## 6. ผู้ให้บริการภายนอกและการส่งข้อมูล

### GitHub Pages
ใช้เผยแพร่ static website ของ GovPrompt

### Cloudflare Worker
ใช้เป็น backend สำหรับ live official search และ security gate ก่อนส่งคำค้นต่อ

### Tavily Search API
ใช้ค้นเว็บตาม official-domain allowlist โดย GovPrompt ตั้งค่าไม่ให้สร้าง AI answer และไม่ขอ raw page content ในคำตอบจาก Search API

เอกสาร Tavily ณ วันที่ตรวจระบุแนวทาง zero data retention แต่ก่อน Public Pilot ต้องตรวจ Privacy Policy, terms, account plan และข้อตกลงที่ใช้จริงอีกครั้ง

### ChatGPT / บริการ AI ภายนอกที่ผู้ใช้เลือก
ปุ่ม “เปิดใน ChatGPT” ของ GovPrompt เป็นการเปิดเว็บไซต์และคัดลอก prompt ไป clipboard ผู้ใช้เป็นผู้วาง prompt หรือแนบเอกสารต่อเอง ไม่ใช่ automatic API submission จากหน้า Home ที่ตรวจ

ก่อนนำข้อมูลไปใช้กับบริการ AI ภายนอก ผู้ใช้ต้องปฏิบัติตามนโยบายหน่วยงานและหลีกเลี่ยงข้อมูลลับ/ข้อมูลส่วนบุคคลที่ไม่จำเป็น

## 7. การเก็บรักษาข้อมูล

แนวทาง Internal Pilot:

- GovPrompt application ไม่ตั้งใจเก็บ full query แบบ persistent จาก flow หน้า Home ที่ตรวจ
- Worker application log ใช้ metadata เท่าที่จำเป็นและไม่ log raw query โดยตรง
- Cloudflare platform logs มี retention ตาม plan/config ของ account ซึ่งต้องยืนยันก่อน Public Pilot
- test data ให้ใช้ข้อมูลจำลองและลบเมื่อสิ้นสุดการทดสอบ

> [ต้องกำหนดก่อนเผยแพร่] ตาราง retention ที่อนุมัติแล้วสำหรับแต่ละ activity และวิธีลบ/ทำลายข้อมูล

## 8. สิทธิของเจ้าของข้อมูล

## 9. เหตุละเมิดข้อมูลส่วนบุคคล

หากสงสัยว่าเกิดเหตุด้านข้อมูลหรือความปลอดภัย ให้หยุด/จำกัดฟังก์ชันที่เกี่ยวข้อง เก็บหลักฐานเท่าที่จำเป็น ประเมินผลกระทบ แก้สาเหตุ และแจ้งผู้รับผิดชอบด้านกฎหมาย/PDPA/DPO เพื่อพิจารณาหน้าที่แจ้งเหตุและเจ้าของข้อมูลตามกฎหมายและระดับความเสี่ยง
