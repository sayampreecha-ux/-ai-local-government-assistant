# GP001 — Official Government Letter Assistant

## Architecture

GP001 is an orchestration module over all six GovPrompt v7 Core services. It owns no
parallel state or policy store. Construction idempotently registers prompt version
`2.0.0`, four knowledge sources, two RBAC policies, and a PDPA approval rule.

The execution sequence is fixed:

1. Validate input and template selection.
2. Route through Transaction Router and activate GP001 in ContextManager.
3. Detect national IDs, email addresses, and telephone numbers without returning raw matches.
4. Retrieve official-letter, administrative, local-government, and PDPA knowledge as needed.
5. Authorize each knowledge source and validate authority/confidence requirements.
6. Authorize and resolve the versioned prompt; PDPA findings require approval.
7. Execute the selected deterministic document template.
8. Validate output against the prompt output contract.
9. Persist workflow selections and legal references to ContextManager.
10. Emit correlated audits, metrics, timing, and errors through Observability.

## Templates

Internal Letter, External Letter, Order, Announcement, Memorandum, and Report share a
canonical output envelope while preserving document-specific sections.

## Knowledge

The local bootstrap catalog includes Local Government, Administrative Procedure,
Official Letter Standard, and PDPA sources. The bundled entries are registry
references and metadata, not copies of legal text. Production adapters must replace
the `govprompt://` references with controlled authoritative repositories.

## Approval behavior

Detected personal data returns `approval_required` before prompt execution. The
caller uses the Governance Layer approval API and may resubmit only under its own
approved orchestration policy. GP001 never logs raw detected values.

## Demo

Run `node demo/gp001-demo.js`. The demo initializes an isolated Core runtime,
generates an internal letter, and prints the structured result plus diagnostic counts.
