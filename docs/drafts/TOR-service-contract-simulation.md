# ร่างขอบเขตของงาน (TOR) จ้างเหมาบริการ — ฉบับจำลอง

> สถานะ: DRAFT / SIMULATION ONLY
>
> เอกสารนี้จัดทำเพื่อทดสอบ Workflow ของ GovPrompt v7.1 โดยใช้ข้อมูลสมมติ ต้องตรวจสอบข้อเท็จจริง ฐานอำนาจ กฎหมายฉบับที่ใช้บังคับ และเอกสารต้นฉบับก่อนนำไปใช้จริง

## 1. ชื่อโครงการ

จ้างเหมาบริการงานธุรการและบันทึกข้อมูล ประจำหน่วยงาน [ระบุชื่อหน่วยงาน]

## 2. หลักการและเหตุผล

หน่วยงานมีความจำเป็นต้องสนับสนุนการปฏิบัติงานด้านธุรการ การจัดเตรียมและจัดเก็บเอกสาร การบันทึกข้อมูล และการประสานงานที่เกี่ยวข้อง เพื่อให้การดำเนินงานเป็นไปอย่างต่อเนื่อง มีความเป็นระเบียบ และสามารถตรวจสอบย้อนหลังได้ โดยต้องไม่กำหนดขอบเขตงานในลักษณะที่เป็นการบรรจุ แต่งตั้ง หรือควบคุมการปฏิบัติงานเสมือนพนักงานของรัฐโดยไม่มีกฎหมายรองรับ

## 3. วัตถุประสงค์

1. เพื่อสนับสนุนงานธุรการและการบันทึกข้อมูลของหน่วยงาน
2. เพื่อจัดเตรียมและจัดเก็บเอกสารให้เป็นระบบ
3. เพื่อเพิ่มความรวดเร็วในการค้นหาและตรวจสอบเอกสาร
4. เพื่อให้มีผลส่งมอบที่สามารถตรวจรับได้อย่างชัดเจน

## 4. ขอบเขตของงาน

ผู้รับจ้างต้องดำเนินงานตามรายการที่หน่วยงานกำหนดในสัญญา เช่น

1. จัดเรียง แยกประเภท และจัดเก็บเอกสารตามระบบที่หน่วยงานกำหนด
2. บันทึกข้อมูลจากเอกสารหรือแบบฟอร์มที่ได้รับมอบหมาย
3. จัดทำบัญชีรายการเอกสารหรือทะเบียนคุมที่เกี่ยวข้อง
4. สนับสนุนการค้นหาและรวบรวมเอกสารตามคำขอของผู้ประสานงาน
5. จัดทำรายงานผลการปฏิบัติงานเป็นรายเดือน
6. ปฏิบัติงานอื่นที่เกี่ยวข้องเฉพาะเท่าที่ระบุไว้ในขอบเขตงานและไม่ขัดต่อกฎหมาย

**ข้อห้ามในการกำหนดงาน:** ห้ามกำหนดอำนาจอนุมัติ อำนาจสั่งการแทนเจ้าหน้าที่ การลงนามในเอกสารราชการ การใช้ดุลพินิจแทนผู้มีอำนาจ หรือหน้าที่ที่มีลักษณะเป็นตำแหน่งประจำของหน่วยงาน เว้นแต่มีฐานอำนาจและรูปแบบการจ้างที่ถูกต้องชัดเจน

## 5. ผลส่งมอบ

1. รายงานผลการปฏิบัติงานประจำเดือน
2. รายการเอกสารหรือข้อมูลที่ดำเนินการในแต่ละงวด
3. ไฟล์หรือเอกสารที่จัดทำตามรูปแบบที่หน่วยงานกำหนด
4. หลักฐานการส่งมอบงานที่ตรวจสอบย้อนกลับได้

## 6. ระยะเวลาการจ้าง

ระยะเวลาจ้าง [ระบุวันเริ่มต้น] ถึง [ระบุวันสิ้นสุด] รวม [ระบุจำนวนเดือน/วัน] โดยแบ่งการส่งมอบเป็น [ระบุจำนวนงวด] งวด ทั้งนี้ต้องสอดคล้องกับงบประมาณ สัญญา และอำนาจอนุมัติ

## 7. วงเงินงบประมาณ

วงเงินงบประมาณที่ใช้ในการจ้าง จำนวน [ระบุวงเงิน] บาท โดยต้องมีหลักฐานการตั้งงบประมาณ แหล่งเงิน การคำนวณราคา และการตรวจสอบความเหมาะสมของราคา ตามกฎหมายและระเบียบที่ใช้บังคับ

## 8. คุณสมบัติของผู้รับจ้าง

1. มีความสามารถตามกฎหมาย
2. ไม่เป็นผู้มีลักษณะต้องห้ามตามกฎหมายหรือระเบียบที่เกี่ยวข้อง
3. มีความสามารถและประสบการณ์ที่จำเป็นต่อขอบเขตงานตามสมควร
4. สามารถส่งมอบงานและรักษาความลับของข้อมูลราชการได้
5. คุณสมบัติอื่นให้กำหนดเท่าที่จำเป็นและมีเหตุผลสัมพันธ์กับงาน โดยไม่จำกัดการแข่งขันเกินสมควร

## 9. วิธีการดำเนินการจัดซื้อจัดจ้าง

ให้เจ้าหน้าที่พัสดุตรวจสอบวิธีการจัดซื้อจัดจ้างที่เหมาะสมจากวงเงิน ลักษณะงาน แผนการจัดซื้อจัดจ้าง และเงื่อนไขตามกฎหมาย ระเบียบ และหนังสือสั่งการฉบับที่ใช้บังคับ ณ วันที่ดำเนินการ โดยห้ามสรุปวิธีการจากวงเงินเพียงอย่างเดียว

## 10. การตรวจรับงาน

1. ตรวจสอบผลส่งมอบให้ตรงตามขอบเขตงานและงวดงาน
2. ตรวจสอบความครบถ้วน ถูกต้อง และใช้ประโยชน์ได้ของเอกสารหรือข้อมูล
3. จัดทำหลักฐานการตรวจรับทุกงวด
4. หากงานไม่ครบถ้วนหรือไม่เป็นไปตามข้อตกลง ให้แจ้งแก้ไขและบันทึกเหตุผลไว้เป็นหลักฐาน
5. ผู้ตรวจรับต้องดำเนินการภายในอำนาจหน้าที่และตามหลักเกณฑ์ที่ใช้บังคับ

## 11. การจ่ายเงิน

จ่ายเงินเป็นรายงวดภายหลังจากผู้รับจ้างส่งมอบงานและผ่านการตรวจรับโดยถูกต้องแล้ว โดยต้องตรวจสอบเงื่อนไขในสัญญา หลักฐานการส่งมอบ การตรวจรับ เอกสารการเบิกจ่าย และภาษีหรือรายการหักที่เกี่ยวข้องก่อนจ่ายเงิน

## 12. การรักษาความลับและข้อมูลส่วนบุคคล

ผู้รับจ้างต้องใช้ข้อมูลเท่าที่จำเป็นตามขอบเขตงาน ไม่คัดลอก เผยแพร่ ส่งต่อ หรือใช้ข้อมูลของหน่วยงานเพื่อวัตถุประสงค์อื่น และต้องปฏิบัติตามมาตรการรักษาความมั่นคงปลอดภัยของข้อมูลและกฎหมายคุ้มครองข้อมูลส่วนบุคคลที่เกี่ยวข้อง

## 13. หลักฐานที่ต้องตรวจสอบก่อนอนุมัติ

- [ ] คำขอหรือบันทึกแสดงความจำเป็น
- [ ] อำนาจหน้าที่และผู้มีอำนาจอนุมัติ
- [ ] แผนการจัดซื้อจัดจ้างหรือหลักฐานกรณีได้รับยกเว้น
- [ ] TOR และขอบเขตงานที่ไม่ซ้ำซ้อนกับภารกิจตำแหน่งประจำ
- [ ] หลักฐานงบประมาณและแหล่งเงิน
- [ ] การกำหนดราคาหรือหลักฐานความเหมาะสมของราคา
- [ ] การตรวจสอบวิธีการจัดซื้อจัดจ้าง
- [ ] ร่างสัญญาหรือข้อตกลง
- [ ] หลักเกณฑ์การตรวจรับและจ่ายเงิน
- [ ] การตรวจสอบกฎหมาย ระเบียบ และหนังสือสั่งการฉบับล่าสุด
- [ ] การประเมินความเสี่ยงด้านแรงงานแฝง/การควบคุมงาน/ข้อมูลส่วนบุคคล

## 14. Decision Lock

หากขาดหลักฐานสำคัญ มีข้อเท็จจริงไม่ตรงกัน ไม่สามารถยืนยันฐานอำนาจ หรือยังไม่ตรวจสอบฉบับกฎหมายที่ใช้บังคับ ให้ตั้งสถานะ `Decision Lock = ON` และแสดงผลเป็น `blocked-missing-evidence` ห้ามสรุปว่าอนุมัติได้หรือดำเนินการได้โดยเด็ดขาด

## 15. ผลการตรวจจำลอง

กรณีทดสอบนี้สมมติว่าข้อมูลข้อเท็จจริง หลักฐาน ฐานอำนาจ และกฎหมายที่ใช้บังคับได้รับการตรวจสอบครบถ้วนแล้ว จึงกำหนดผลจำลองเป็น:

- Fact Completeness: PASS
- Applicable Authority Check: PASS
- Legal Version Gate: PASS
- Evidence Gate: PASS
- TOR Compliance: PASS
- Risk & Conflict Check: PASS
- Decision Lock: OFF (เฉพาะสถานการณ์จำลอง)

## 16. ข้อจำกัด

ผลการทดสอบนี้ไม่ใช่การอนุมัติ ไม่ใช่ความเห็นทางกฎหมายเฉพาะกรณี และไม่อาจใช้แทนการตรวจสอบเอกสารจริงของหน่วยงานหรือการพิจารณาของผู้มีอำนาจได้
